# 機捷更新與改班核實

機捷更新先保存原始來源，再分別判斷資料完整性與班表異動。正常小幅改班自動更新；核實紀錄不會略過資料完整性檢查。

## 更新結果

- `accepted`：資料一致、服務完整，且沒有需核對的異動，或異動已按精確來源版本核實。
- `scheduled`：已取得有明確生效日的未來班表，保留現行版本，依營運日切換。
- `needs-review`：減班超過 30%，或首末班變動至少 60 分鐘，保留先前資料並產生逐日、逐方向報告。
- `invalid`：缺站、方向矛盾、引用不存在的停靠模式、起站或終點不在停靠模式、時間不合法、缺少旅行時間等，拒絕發布。

每個日期會檢查所有車站與 A18 之間雙向服務；兩份資料只有在該日期都適用時才比較班數。不以已過期的活動加班表推估未來服務。30% 是觸發核對的門檻，不代表減班一定不合法。

## 核實並接受正式改班

1. 在 GitHub Actions 的更新執行頁閱讀「機捷更新」摘要，下載 `metro-update-report` 附件（保存 30 天）。內容含 `candidate.raw.json`、`report.json`、`summary.md`；成功時另有精簡後的 `candidate.json`。
2. 對照桃捷官方時刻表／公告，確認適用起訖日期、受影響日期、方向、首末班、普通／直達／跳站的實際停站。多次下載相同資料本身不算官方佐證。
3. 在 `scripts/metro-reviews.json` 增加該來源 `sourceHash` 的核實紀錄，填 `reviewedAt`、`reason`、官方 HTTPS `sources` 及 `validity.from/through`。資料指紋忽略 API 刷新時間、版本流水號與陣列順序，但包含所有班表、停站及抵達時間內容。來源內容變動後，舊核實紀錄不會套用。
4. 若原始欄位互相矛盾，只能附上已核實的限定班次修正：使用起站、方向、整列目的地、平假日標籤、原發車時間、原車種與原停靠模式唯一對應；可補停靠模式、每班終點、專屬旅行時間與乘客可讀名稱。不能新增或改寫發車時間。新模式需附官方停站依據。
5. 跑單元測試與建置、提交核實紀錄，重新執行每日更新。沒有對所有未來版本放行的環境變數或全域略過開關。

TDX 若省略 `Direction`，本站只在機捷已知線形上能由明確起迄站唯一確認方向時補入；明確填錯的方向仍會被攔截。其他缺漏不以猜測補齊。

## 日期與舊資料

- 已知適用期間只服務該期間的營運日。未來版本不提前啟用，較新版本到期後不會復活舊版。
- 改班時保留必要的前一營運日，以處理午夜後末班車。更新失敗不改寫原取得時間。
- 未知適用期可依常態規則推估查詢範圍，但超過 **七個實際日**未取得新資料就停止提供機捷行程；此期限不是把未來查詢範圍縮成七天。
- 來源未提供日期的新版本不覆蓋已有明確效期的班表；需先核對適用期間。
- A18 與高鐵桃園的單純步行接駁不依賴機捷班表。
